==================================================
8. COMMISSION / REWARD
==================================================

Do NOT mix commission with the order value.

Show separately:

Commission Rate: 5%

Commission Amount:

Eligible Amount × 5%

User Reward/Profit:

Eligible Amount × configured reward rate

Example:

Order Total:          $500
Commission Rate:        5%
Commission:             $25

User reward:            $X

The exact rate must be configurable from
Commission Settings.

The order must store a snapshot of the rate
used at the time the order was created.

9. BALANCE CHECK
==================================================

After calculating the order:

Available Balance: $300
Order Requirement: $500

System calculates:

Shortfall = $500 - $300
Shortfall = $200

Display clearly:

AVAILABLE BALANCE       $300
ORDER REQUIREMENT       $500
FUNDING SHORTFALL       $200

Do NOT secretly create a negative balance.

If the business allows credit/deficit,
show it explicitly to both Admin and User:

"Additional funds required: $200"

The user must know why funds are required.

==================================================
12. USER TASK OWNERSHIP
==================================================

A task assigned to User A MUST NOT appear
for User B.

Backend must use authenticated user ID.

Never trust:

?user_id=123

from the browser.

Every task must contain:

assigned_user_id

The backend must verify:

authenticated_user_id == assigned_user_id

before allowing the user to view or complete it.

==================================================
14. ORDER COMPLETION
==================================================

User opens task.

System verifies:

- Correct user
- Task exists
- Task is active
- Order has not already been completed
- Required conditions are satisfied

When completed:

1. Mark task COMPLETED.
2. Mark order COMPLETED.
3. Release/resettle reserved funds according
   to the configured business rules.
4. Record commission.
5. Record user reward/profit.
6. Create ledger entries.
7. Update today's task count.
8. Create audit record.

All operations must happen inside a database
transaction.

==================================================
17. SECURITY
==================================================

All calculations must happen on the backend.

Never trust prices, commission,
balance or task status sent from frontend.

Use decimal/integer-money arithmetic.

Prevent:

- Double completion
- Double deduction
- Double refund
- Duplicate order creation
- Unauthorized task access
- Unauthorized balance modification

Use database transactions and idempotency.
